# Terminal overview implementation plan

User request: a comprehensive display page. Preserve the established terminal-only
scope and the existing detailed candlestick view. Default to a new overview;
`--view chart` / `view = "chart"` retains direct access to the original chart.

Design: six coordinated panels for CPU, memory, disk read/write, network RX/TX,
swap, and load 1/5/15, exposing all ten metrics. At >=100x36 use a 2x3 chart grid.
At >=80x22 use a ten-metric watchlist plus a large focused candle chart. Smaller
supported terminals show a compact ten-metric table. Keep period, zoom, history,
pause, ASCII, line mode and errors consistent. Tab/Up/Down select metrics; Enter
opens the selected detail; o toggles overview/detail; Esc returns from detail.

Use batched SQLite readers for all metric candles and sampled points, retaining
NULL/gap semantics and indexed bounded queries. A single query per batch avoids
ten repeated scans and gives all panels the same database snapshot. Commands
perform reads off the render path; revision tokens reject stale layout responses.

- [x] Write RED tests for batched OHLC/raw/point readers, all metrics and gaps.
- [x] Implement batch history queries and verify existing storage regressions.
- [x] Write RED tests for overview default/config/CLI, navigation, shared window,
      resize/layout/ASCII, stale data and paused views; implement model and view.
- [x] Update help, README/example config, and PTY smoke; inspect actual terminal
      frames at 120x40, 80x24 and narrow sizes, plus the detailed chart view.
- [ ] Run full tests, race, vet, native and Linux builds; review, commit and push

Scope limits: no browser or web server, no new sampling source or retention
schema. Sparse history is not filled. Unavailable metrics remain n/a/NULL.
